## 3. 数据口径核对结论

- 后端测试：`AlgorithmTest` 6 项 + `ApiIntegrationTest` 17 项 = 23 项，H2 与 MySQL 8.0 各跑一轮，
  两轮均 `failures=0 errors=0`。
- HTTP 冒烟：27 次请求全部通过，汇总数据 `income=1000.00`、`expense=236.00`、`balance=764.00`。
- 算法口径：IQR 窗口为待测日期前 90 天、样本不少于 8 笔、上界 `Q3+1.5×IQR`、严格大于才判定异常；
  8 笔样本 `[10,12,14,16,18,20,22,24]` 的上界为 31.00，31.00 正常、31.01 异常。
- 预算口径：`usageRate = spent / amount × 100`，两位小数；`<80%` 正常、`80%—<100%` 接近上限、
  `≥100%` 已超支；未设置预算返回 `NOT_SET`。

结论：文档、代码与实测三处一致，无需修正后端逻辑。

## 4. 验收演练（后端侧）

1. `GET /api/health` → `{"code":0,"message":"成功","data":{"status":"UP"}}`；
2. 未带令牌访问 `/api/bills` → 401；带令牌访问他人账单 → 404；
3. `POST /api/bills` 校验：金额 0、未来日期、类型与分类不一致均返回 400；
4. 预算 `PUT /api/budgets/{month}` 后 `GET` 返回同一 `usageRate` 与状态；
5. 退出登录后旧令牌立即 401（`token_version` 递增生效）。
