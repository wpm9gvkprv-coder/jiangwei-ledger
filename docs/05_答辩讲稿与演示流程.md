# 后端答辩讲稿与演示流程

## 个人工作说明
我负责数据库设计、后端接口和智能算法。数据库包含用户、分类、账单、预算和异常提醒；Spring Security配合JWT识别用户，业务层按用户ID限制访问；MyBatis-Plus完成持久化。
统计接口为前端提供收支总额、分类占比及月度趋势。预算按月计算，关键词规则用于消费类别建议，IQR用于标记潜在大额异常。

## 演示顺序
1. 展示ER图及5张表，说明默认分类与个人分类的关系。
2. 注册并登录，将令牌带入账单请求；用第二用户读取第一用户账单，展示404。
3. 新增收入1000和支出20，查询月度统计，核对结余980。
4. 将月预算设置100；累计支出达到80和100时查看不同状态。
5. 输入“学校食堂午餐”，展示关键词匹配与手动确认；输入未知描述展示NO_MATCH。
6. 使用8条历史支出[10,12,14,16,18,20,22,24]，新增100元支出，解释Q1=13.5、Q3=20.5和上界31。
7. 将异常支出改为20，展示提醒移除；删除历史样本导致不足8条时也不再提示确定异常。
8. 退出登录后再次请求受保护接口，展示旧令牌失效。

## 常见问题
为什么不用机器学习？本项目周期短、样本少，规则和统计方法更容易解释、验证与维护。
算法是否判定消费不合理？不是。它只依据个人历史数值提示核对，合理的大额购买也可能被标记。
如何防止越权？所有查询和写入使用JWT中校验过的用户ID，拒绝访问他人账单、类别、预算和提醒。
为什么金额不用double？BigDecimal与数据库DECIMAL避免累计浮点误差。
修改历史账单会怎样？同一事务中重算提醒，按用户行锁串行化账单变更，防止遗留失效提醒。
可改进之处？大数据量下改为增量窗口；公网部署增加限流与运维措施；取得前端后完成真实页面联调。
