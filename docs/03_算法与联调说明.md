# 第三阶段 算法与联调说明

## 关键词分类
在同一收支类型内匹配描述，英文不区分大小写。优先选择最长关键词；同长度时依固定规则顺序：餐饮、交通、购物、娱乐、工资，以及各类别内的词条顺序。
例如“电影外卖”中两词同长，按餐饮优先返回“餐饮”；“出租车和外卖”返回“交通”。没有匹配时返回NO_MATCH和空类别，用户手动选取。推荐不会自动保存账单。
关键词表见KeywordClassifier.java。只推荐系统默认类别，用户可自行改选个人类别。

## IQR异常检测
仅分析支出；按账单日期、ID升序确定历史先后；同日较小ID的账单也可作为历史。
窗口为待检测账单日期之前90天（含边界）及同日先前记录，排除自身和未来日期记录；严格按当前认证用户隔离。
样本少于8条返回INSUFFICIENT_DATA，不产生异常提醒。
对排序数组x，位置h=(n-1)p，分位数Q(p)=x[floor(h)]+(h-floor(h))×(x[ceil(h)]-x[floor(h)])。
Q1=Q(0.25)，Q3=Q(0.75)，IQR=Q3-Q1，上界=Q3+1.5×IQR；仅当金额严格大于上界时为ANOMALY。
边界相等视为NORMAL；IQR=0时仍沿用上界规则。金额与阈值采用BigDecimal计算。
例：历史[10,12,14,16,18,20,22,24]，Q1=13.5，Q3=20.5，IQR=7，上界31；31正常，31.01异常。
每次账单增改删后，在同一事务内重算该用户提醒；删除或修正异常账单后移除失效提醒。金额/阈值变化的提醒重新置为未读。通过用户行锁串行化同一用户账单写入。
本实现全量重算的最坏复杂度为O(n² log n)，适合课程小数据集；大规模使用需增量窗口及异步任务。

## 预算预警
月支出为当月EXPENSE金额之和。使用率=支出/预算×100%，保留2位小数；阈值判断使用原始金额，避免四舍五入误报。
无预算返回NOT_SET，amount/usageRate/remaining为null；小于80%为NORMAL；达到80%且小于100%为NEAR_LIMIT；达到100%为EXCEEDED。预算必须大于0。
预算预警按查询实时计算，不与单笔异常提醒混为一类。

## 前端联调清单
1. Axios携带Authorization: Bearer <token>；401时回登录页，404不区分不存在与他人记录。
2. 登录后读取分类；记账前调用分类推荐，允许人工确认；账单保存后刷新统计、预算和提醒。
3. 月度统计字段income/expense/balance；类别统计name/amount/percentage；趋势数据按月排列并补零。
4. 预算按status显示；异常检测展示sampleCount和upperBound，数据不足时提示积累样本。
5. 分页读取records/total/page/size；无数据时展示空状态，金额按两位小数展示。
6. 使用Postman集合和自动化API测试验证契约；与庞润泽的真实Vue页面联调仍需在取得前端后执行。
